## Why this matters

Oh My Code is a native macOS editor (Swift 6, SwiftUI + AppKit) developed by one person at a high pace (two releases on 2026-11-19 alone). There is no CI: `scripts/release.sh` publishes an update to every installed copy (via Sparkle) without checking that the build or tests pass. Several rules that break things when forgotten exist only in the maintainer's head — most importantly "run `xcodegen` after adding a file" and "tests must never write to the user's real settings, `~/Library` or `~/.claude`". Other plans in `plans/` will be executed by AI agents; they need these rules written down in `CLAUDE.md`, and a CI run to tell them whether they broke something.

## Steps

### Step 1: Write `CLAUDE.md`

Create `CLAUDE.md` at the repo root (plain Markdown, ≤ ~120 lines) with these sections, using the facts in "Current state" (copy commands exactly):

1. **What this is** — one paragraph: native macOS code editor, Swift 6 strict concurrency, SwiftUI + AppKit + TextKit 2, XcodeGen, Swift Testing.
2. **Build and test** — the commands table above; how to run one suite (`-only-testing:OhMyCodeTests/<Suite>`) and one test (`-only-testing:OhMyCodeTests/<Suite>/<testName()>`); that the full run takes ~7 min; database tests need `scripts/dbtest/start.sh` (else they skip).
3. **Adding files** — "After adding, moving or deleting a Swift file or resource, run `xcodegen generate` and commit `OhMyCode.xcodeproj/project.pbxproj` with your change. The build fails or misses files otherwise."
4. **Tests must not touch the user's data** — any new persisted state (UserDefaults, files in Application Support, Keychain, `~/.claude`) must branch on `AppSettings.isRunningTests` like `RecentFolders.shared` in `OhMyCode/App/OpenRequests.swift:269`, using `ScratchDefaults.named(...)` or a temporary directory; never call `UserDefaults.standard` directly (use `UserDefaults.omc`); `OMC_SUPPORT_DIR` isolates a manually launched app.
5. **Conventions** — Swift 6 strict concurrency (no new `@unchecked Sendable`/`nonisolated(unsafe)` without a comment saying why); doc comments in plain English explaining *why*; match the surrounding file.
6. **Commits and changelog** — Conventional Commits (examples above), no AI attribution trailers; user-visible changes get an entry under `## [Unreleased]` in `CHANGELOG.md`; releases are made only with `scripts/release.sh <version>` by the maintainer.

Then create `AGENTS.md` with: `See [CLAUDE.md](CLAUDE.md) — it applies to every agent.`

### Step 2: Add the CI workflow

Create `.github/workflows/ci.yml`:

```yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:
jobs:
  test:
    runs-on: macos-latest
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v4
      - name: Xcode version
        run: xcodebuild -version
      - name: Install XcodeGen
        run: brew install xcodegen
      - name: Project is up to date
        run: |
          xcodegen generate
          git diff --exit-code -- OhMyCode.xcodeproj
      - name: Build and test
        run: >
          xcodebuild test -project OhMyCode.xcodeproj -scheme OhMyCode
          -destination 'platform=macOS' -only-testing:OhMyCodeTests
          -skip-testing:OhMyCodeTests/PerformanceGuardTests
          -skip-testing:OhMyCodeTests/KeystrokeGuardTests
          CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM=
```

Notes: the timing suites are skipped in CI because shared runners are slow and noisy (they still run locally). The "Project is up to date" step catches a forgotten `xcodegen`. If the hosted runner's default Xcode is older than the one the project needs, add a step before "Xcode version" that selects the newest installed Xcode: `sudo xcode-select -s "$(ls -d /Applications/Xcode*.app | sort -V | tail -1)"`.

**Verify**: `ruby -ryaml -e 'YAML.load_file(".github/workflows/ci.yml")'` → exit 0. Locally, run the same test command (with the two `-skip-testing` flags) → `✔ Test run with … passed`.

### Step 3: Make the README's test section point at the fast commands

In `README.md`, subsection `### Build & test from CLI` (under `## Development`), keep the two existing commands and add one line showing a single-suite run (`-only-testing:OhMyCodeTests/SessionTests`) and a sentence: "Rules for contributors and agents are in [CLAUDE.md](CLAUDE.md)."

**Verify**: `grep -n "only-testing:OhMyCodeTests/SessionTests" README.md` → one match; `grep -n "CLAUDE.md" README.md` → one match.

### Step 4: Refuse to release a commit whose CI failed

In `scripts/release.sh`, inside the `if ! $local_mode; then` block shown above, right after the `[[ $(git rev-parse HEAD) == $(git rev-parse origin/main) ]] ...` line, add:

```sh
    # The commit being released passed CI (skip with OMC_RELEASE_SKIP_CI=1, e.g. CI is down).
    if [[ ${OMC_RELEASE_SKIP_CI:-} != 1 ]]; then
        ci=$(gh run list -R $REPO --workflow ci.yml --commit "$(git rev-parse HEAD)" --json status,conclusion \
            --jq '.[0] | "\(.status) \(.conclusion)"' 2>/dev/null)
        [[ $ci == "completed success" ]] || die "CI for $(git rev-parse --short HEAD) isn't green (${ci:-no run}); wait for it or set OMC_RELEASE_SKIP_CI=1"
    fi
```

(`REPO` and `die` are already defined at the top of the script.) Also document `OMC_RELEASE_SKIP_CI=1` in the script's header comment, next to the existing usage lines.

**Verify**: `zsh -n scripts/release.sh` → exit 0; `grep -c "OMC_RELEASE_SKIP_CI" scripts/release.sh` → `3` or more. Do NOT run a real release.
