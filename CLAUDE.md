# Oh My Code: rules for contributors and agents

## What this is

Oh My Code is a native macOS code editor written in Swift 6 with strict concurrency checking. It uses
SwiftUI and AppKit, with TextKit 2 for the text view. The Xcode project is generated by XcodeGen from
`project.yml`, and the tests use Swift Testing (about 850 tests in `OhMyCodeTests/`).

## Build and test

| Purpose | Command |
|---|---|
| Generate project | `xcodegen generate` |
| Build | `xcodebuild build -project OhMyCode.xcodeproj -scheme OhMyCode -destination 'platform=macOS'` |
| One suite | `xcodebuild test -project OhMyCode.xcodeproj -scheme OhMyCode -destination 'platform=macOS' -only-testing:OhMyCodeTests/SessionTests` |
| All tests | `xcodebuild test -project OhMyCode.xcodeproj -scheme OhMyCode -destination 'platform=macOS' -only-testing:OhMyCodeTests` |
| Shell syntax | `zsh -n scripts/release.sh` |

- One test: `-only-testing:OhMyCodeTests/<Suite>/<testName()>`.
- The full run takes about 7 minutes. Prefer one suite while you work.
- Database integration tests skip themselves unless `TEST_RUNNER_OMC_TEST_POSTGRES_URL` /
  `TEST_RUNNER_OMC_TEST_MYSQL_URL` are set. `scripts/dbtest/start.sh` starts throwaway servers
  (`scripts/dbtest/stop.sh` stops them).
- `PerformanceGuardTests` and `KeystrokeGuardTests` measure wall-clock time and can fail on a slow
  or busy machine. CI skips them.

## Adding files

After adding, moving or deleting a Swift file or resource, run `xcodegen generate` and commit
`OhMyCode.xcodeproj/project.pbxproj` with your change. The build fails or misses files otherwise.
The generated `OhMyCode.xcodeproj` is committed on purpose; CI checks that it is up to date.

## Tests must not touch the user's data

Tests must never write to the user's real settings, `~/Library` or `~/.claude`. Isolation is opt-in per
store, so any new persisted state (UserDefaults, files in Application Support, Keychain, `~/.claude`)
must branch on `AppSettings.isRunningTests`, like `RecentFolders.shared` in
`OhMyCode/App/OpenRequests.swift`:

```swift
static let shared = RecentFolders(defaults: AppSettings.isRunningTests ? ScratchDefaults.named("recent") : .omc)
```

Use `ScratchDefaults.named(...)` or a temporary directory in tests. Never call `UserDefaults.standard`
directly; use `UserDefaults.omc`. For a manually launched app, `OMC_SUPPORT_DIR=<folder>` keeps its
Application Support data, defaults and `~/.claude/ide` lock files inside that folder and leaves the
Keychain alone.

## Conventions

- Swift 6 strict concurrency. Don't add `@unchecked Sendable` or `nonisolated(unsafe)` without a
  comment saying why it is safe.
- Doc comments are plain English and explain why, not what.
- Match the surrounding file's style. There is no formatter or linter.

## Commits and changelog

- Conventional Commits in English, for example `feat: a spell checker for comments, strings, Markdown and names`,
  `build(release): unregister the release build's app copies`, `docs: ...`, `chore(release): 0.2.5`.
  No AI attribution trailers.
- User-visible changes get an entry under `## [Unreleased]` in `CHANGELOG.md` (`### Added` /
  `### Changed` / `### Fixed`).
- Releases are made only by the maintainer, with `scripts/release.sh <version>`.
